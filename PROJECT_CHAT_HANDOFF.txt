PROJECT HANDOFF / PROMPT CONTEXT

Project name:
Franka-Robot-Real-to-Sim-Teleoperation-VR-Pointcloud-Simulation

Primary end goal:
Build a stable Meta Quest 3 teleoperation / visualization workflow for a Franka robot simulation where:
- Unity project IRIS-Meta-Quest3 is the active Quest application.
- SimPublisher is the active Python-side publisher.
- The user can see the robot, point clouds, and a wrist camera panel in VR.
- The wrist camera panel is mounted on the robot itself, not floating in front of the viewer.
- Point clouds are useful, aligned, and performant enough for Quest.

Active project scope:
- We worked in these two codebases only:
  1. IRIS-Meta-Quest3
  2. SimPublisher
- We did NOT intentionally build the workflow around MVPointCloudVR or other side projects.

High-level architecture:
- SimPublisher renders MuJoCo camera RGB/depth and publishes:
  - RGBD topics
  - point cloud topics
- IRIS-Meta-Quest3 subscribes to those topics in Unity and renders:
  - point clouds
  - the wrist camera panel
  - the robot scene

Current desired runtime behavior:
- Wrist panel feed: wrist camera only
- Workspace / debugging camera: top replaces front
- Active point cloud cameras: top, right, left
- Front point cloud is no longer part of the active workflow
- Wrist camera panel should be parented to the robot hand link (with link7 fallback), using local offset/rotation
- Viewer-facing fallback behavior should not be the production path

Current point cloud tuning concepts
========================================

Important publisher-side arguments:
- --w / --h
  Controls the rendered sensor resolution before point-cloud extraction.

- --pc_stride
  Controls how densely pixels are sampled from the depth image.
  Lower stride = denser cloud.
  Higher stride = sparser cloud.

- --pc_max_points
  Global hard cap after filtering.

- --pc_max_points_top
  Optional top-camera-only hard cap.

- --pc_min_depth / --pc_max_depth
  Near/far filtering range for point generation.

- --pc_clip_below_table
  Removes points below the table plane.

- --pc_table_clearance / --pc_top_table_clearance
  Safety margin above the table before clipping.

- --pc_object_only
  Restricts points to a workspace AABB.

- --pc_object_bbox_min / --pc_object_bbox_max
  The world-space bounds for that object-only crop.

- --pc_no_anchor_auto_translate
  Disables anchor-based automatic translation correction.
  This is useful when stable, predictable alignment is preferred over runtime auto-adjustment.

Important Unity-side knobs:
- SimPubPointCloudSubscriber.maxPoints
  Unity receive-side cap

- SimplePointCloudRenderer.pointSize
  Visual size of rendered points

- PointCloudPoints shader _PointSize
  Shader-side point size

Important non-obvious detail:
- The point-cloud payload includes a point size field, but Unity currently ignores the per-point size in the subscriber path.
- Visible point size is controlled by Unity's point renderer/shader, not by the payload's size channel.

Current recommended / working command pattern
========================================

Baseline working launch pattern:

.\.venv\Scripts\python.exe .\SimPublisher\AG\franka_quest_unified_publisher.py `
  --xml "$LAB_XML" `
  --host "$HOST_IP" `
  --unity_node "$UNITY_NODE" `
  --bind_ip 0.0.0.0 `
  --visible_geoms_groups 2 `
  --fps 30 --w 640 --h 480 `
  --cams wrist top right left `
  --pc --pc_cams top right left `
  --pc_stride 4 --pc_max_points 20000 `
  --pc_min_depth 0.08 --pc_max_depth 2.8 `
  --pc_intrinsics_mode mujoco `
  --pc_clip_below_table --pc_table_clearance 0.02 --pc_top_table_clearance 0.035 `
  --pc_object_only --pc_object_bbox_min 0.35 -0.35 0.40 --pc_object_bbox_max 0.90 0.35 0.85 `
  --cam_extrinsics_profile lab_standard `
  --pc_no_anchor_auto_translate `
  --robot_start_preset reverse_u `
  --show_mujoco_window `
  --object_control `
  --object_step_xy 0.01 --object_step_z 0.008 --object_move_rate_hz 10
